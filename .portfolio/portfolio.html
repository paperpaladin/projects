Systems engineering portfolio · Linux / FOSS

Thirty-eight programs, and something outside each one that decides if it is right.

Every project here is built against an external oracle — gcc and clang, the Linux kernel, dash, GNU tar, readelf, SQLite, Python's own regex engine. Not one of them is the judge of its own correctness. That constraint is the whole method, and it is why 10 of the 18 defects recorded here were in the test harness rather than in the code.

Every figure in this document is generated from the repositories themselves: commit counts from git, line counts from the files, test counts from running each suite. Nothing is transcribed by hand.

The method

A test you wrote, checking code you wrote, against a number you worked out yourself, proves that you were consistent. It does not prove you were right. Every project here is measured against an authority it does not control.

Why this matters more than it sounds

The first run of almost every harness in this project passed. The useful question is never “do my tests pass” but “have I watched this harness fail?” Where that question got asked, it usually turned out the answer was no — and the suite had been reporting success because it was silently doing nothing.

Scale

Source against tests

33,073 lines of tests to 49,150 of source. The ratio is the point: in several of these the harness is the project, and the program under test is scaffolding for it.

A number worth distrusting

Test counts are not comparable between these repos and are deliberately not charted together. wasmi's 11,833 are generated arithmetic cases; jail's 77 are hand-written assertions against kernel behaviour, and each one took longer to get right than a thousand of the former. Plotting them on one axis would imply a comparison that does not exist.

What went wrong in the harness

These are the defects worth reading. In each case the code looked fine, the suite was green, and the thing that was broken was the thing meant to find breakage.

inflatemake test-asan could not fail

Reject tests assert exit code exactly 1; AddressSanitizer also exits 1. Found by deleting the classic dist > o->n bounds check and watching 146 tests pass while ASan printed a heap overflow to stderr. Fixing the exit code revealed that every malformed input had also been leaking 192KB, invisible for the same reason.

walkvHalf the crash matrix never crashed

In torn-write mode the fsync boundary called the injection hook and discarded its return value, so every fsync scenario ran to completion and reported a perfect result.

walkvFour planted defects, only one caught

Mutation testing showed the matrix crashed, recovered, verified and then stopped — nothing ever wrote after a recovery, so a subtly wrong recovery was unobservable. Adding that one scenario took the suite from 83 to 163 and the defect now fails 20 of them.

tarxEvery symlink assertion was vacuous

diff -r dereferences symbolic links, so the comparisons silently compared targets instead of links, and a dangling link aborted the diff outright.

srcdiffSixteen false positives on a clean release

Against the genuine xz-5.4.5 tarball and its git tag, every HIGH finding was wrong — and each was an m4/*.m4 file absent from git, the exact shape of the attack it exists to find. The real signal would have been one line in seventeen.

dwarfdumpASan's exit code collided with “malformed input”

Both are 1, so the robustness sweeps would have scored a genuine heap overflow as a clean diagnostic.

unreproReported REPRODUCIBLE because make did nothing

Pointed at four sibling repos it compared zero outputs and called them clean. Zero outputs is now inconclusive.

commitqThe commit gate was not gating 12 of 18 repos

The test command was a hardcoded table of six names; everything else returned success, so two thirds of the project could be committed without running anything.

slabgcc deleted the oracle

At -O2 gcc knows what calloc promises, so it proved the zero-checking loop could not observe a non-zero byte and removed it. An allocator that never zeroed anything passed cleanly.

ccFive hand-computed expectations were wrong

Each cost a detour through “is this a codegen bug?” The compiler was right every time. t/addcase.sh now takes the expected value from gcc and refuses the case if clang disagrees.

What went wrong in the code

Found by the oracles, never by re-reading the source. Each of these produced plausible output and passed every check that existed at the time.

rxThe linear-time guarantee was quietly broken

Injecting a start thread at every input position collided with the generation marks — and that dedup is the guarantee. The one bug that destroyed the project's only interesting property.

lnkA binary the kernel refused to run

File offset and virtual address were aligned independently. BASE 0x400000 is divisible by every power of two up to 4MB, so they stayed in step by arithmetic luck until an 8MB-aligned array broke the congruence. The fix made the whole class unemittable rather than merely fixed.

jailA perfect sandbox applied to the wrong process

The rule-installing loop reused the argument parser's index, so jail built a flawless ruleset and then exec'd --ro. Every internal invariant held; only a real program reporting a real errno could see it.

dwarfdumpStrings resolved to different real strings

clang emits DW_AT_name as strx1 before declaring str_offsets_base on the same DIE. Every lookup succeeded, no error, no marker — the second unit was simply named main.c where readelf said lib.c.

traceA SIGTERM death reported as exit 0

After passing a signal through, the tracee was already running, so the next PTRACE_SYSCALL hit ESRCH. Reintroduced once by a later refactor and caught again immediately by the same test.

profA race against the dynamic loader

A one-shot /proc/PID/maps snapshot raced ld.so, truncating libc frames non-deterministically.

sqlrA closing paren ended the column list

Depth was decremented and tested in the same iteration, so the ) of VARCHAR(10,2) looked like the end of the CREATE statement. SELECT * returned one column of four, with no error.

srcdiffA funding link parsed as a repository

github.com/sponsors/hynek resolved to owner sponsors. No offline test could reach it: the bug was in metadata resolution, and the tests all covered the comparison.

How this is kept honest

Every commit builds. Verified by checking out each one in turn, deleting build artifacts so a stale binary cannot fake a pass, and rebuilding.

All 38 build reproducibly. Proven by unrepro, one of them, which found that eight of its siblings were not — -g writes the compiler's working directory into DWARF .debug_line_str. Every repo compiling with -g was affected and every repo without it was already clean, which is independent confirmation of the cause rather than a plausible guess.

No commit can be gated by a suite that does not run. commitq runs each repo's tests against the working tree before committing and refuses when they fail — or when a repo has no discoverable suite at all, which was a real bug it had for two thirds of the project.
