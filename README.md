# projects

Thirty-eight programs, each checked against something that does not care
whether I am right.

Pure C or standard-library Python. No frameworks, no package managers: the
only third-party library any of them links is `zlib`, in one repo (`walkv`);
otherwise it is libc, plus `libm` in three and `libpthread` in one. The
oracles listed below are external *programs*, run at test time and compared
against -- not linked.

Every repository has `make test`, and the number it prints is generated by
running it rather than typed by hand.

## Check it yourself

Every repository is independent and depends on nothing but a C compiler and
Python 3. Clone one, run its suite:

```sh
git clone <this>/sqlr && cd sqlr && make test
```

**All 38 pass from a clone of themselves alone**, with no sibling repository
present and nothing cached: 547 seconds for the whole collection, median 7s,
slowest 132s (`tzf`, which sweeps every zone file it can find). That is
checked rather than claimed -- `make audit-deep` in this repository clones
each one to a scratch directory with no neighbours and runs `make test`
there.

It was 37 of 38 until that check was first written. `gitobj`'s suite required
eight named sibling repositories to exist at `../<name>/.git`, so for anyone
who cloned it alone it failed five assertions -- including a corruption test
that, finding no corpus, planted no corruption and then reported that
corruption was not detected. It builds its own corpus now.

A few need an external tool to compare against, and the handling differs by
how much of the oracle that tool *is*:

- **`corex` refuses to run without `gdb`** (exit 2, one line saying why).
  gdb is the only oracle for every fact it checks and also the only way to
  obtain a core here, so a reduced run would report "0 passed, 0 failed"
  having checked nothing -- which is the failure this collection is about.
- **`trace` skips its strace comparison loudly** (`SKIP strace not installed,
  differential oracle unavailable`) and keeps going, because strace is one
  oracle among several there.
- **`jail` checks the Landlock ABI first** and skips with the reason if the
  kernel is older than 5.13, rather than passing because nothing was denied.

`valgrind` is only needed for the optional `make test-valgrind` targets.

## The rule

A test I wrote, passing against an implementation I wrote, proves that I was
consistent. It does not prove that I was correct. So every repository here is
judged by something outside my control:

- **`cc`** is a C compiler. Its tests compile each case with `cc`, `gcc`, and
  `clang`, run all three, and require identical output. Disagreement is a bug
  in `cc` by definition, because the other two are the standard.
- **`sqlr`** reads SQLite database files. Its oracle is `libsqlite3` itself,
  driven through `ctypes`, with a version-equality check so the comparison
  cannot silently drift to a different format.
- **`jail`** builds Landlock sandbox policies. Nothing in the test suite
  decides whether a path is denied -- the kernel does, and the suite asserts
  the syscall returned `EACCES`.
- **`bigint`** implements arbitrary-precision arithmetic. 107,571 operations
  are compared against Python's native `int`.
- **`srcdiff`** finds shipped code that is absent from a project's repository
  -- the discrepancy that was the `xz` backdoor. The compromised 5.6.1 tarball
  has been purged from the archives it would be fetched from, so the fixtures
  reproduce the *technique* against a clean 5.4.5 release: the genuine
  `build-to-host.m4`, serial left intact, one comment appended, no malicious
  content of any kind. Detection keys on provenance and never on recognising a
  payload, which is the only reason it generalises past that one incident --
  and `srcdiff`'s own README says so under "Why the sample is not the real
  one", along with the one false positive it leaves in rather than widening a
  normalisation rule to absorb.

When no external authority exists, the oracle is a second independent
implementation, a metamorphic property, or the format's own published vectors
-- never the program itself.

## What the tests are worth

The hardest defect class in this collection is not wrong code. It is a test
that passes while proving nothing, and every repository has produced at least
one.

`xmlc` reported `897/897`. That number was meaningless: the harness counted a
"not implemented" exit the same as "well-formed", so the two thirds of the W3C
suite the parser could not yet read were scored as passes. Separating the two
turned `897/897` into `98/98 of 121 judged, 1553/1674 declined`, and dropped
the count of cases the parser should have caught from 749 to 2. The honest
number is smaller and the work is better.

`rx` pinned a pathological-backtracking case to exit status `{0,1}` -- which
accepted a timeout, a crash, and a correct answer equally. It now pins exit
`1`, requires the 1MB subject to be at least 1,000,000 bytes, and requires
`timeout` to report `124` for the Python reference it is beating.

`METHOD.md` is the standing list of these: the shapes a vacuous assertion
takes in shell and Python, and the ones that have already cost real time
here.

## Reproducible builds

`unrepro` -- itself one of the thirty-eight -- builds a project twice under
deliberately different conditions (directory name, `TZ`, locale, `umask`,
hostname, user, `-j`, `SOURCE_DATE_EPOCH`) and compares the outputs byte for
byte. It diagnoses seven planted causes, 7 of 7: timestamps, `__DATE__`,
build paths, filesystem ordering, ASLR, locale, parallelism.

Pointed at every sibling: **34 of 38 verify as REPRODUCIBLE.** The other four
are the Python repos, where `make -B` produces nothing to compare and the tool
reports *inconclusive* rather than counting an empty comparison as a pass --
which is a distinction it learned the hard way, having once printed
`REPRODUCIBLE (0 output(s))` for a tree where `make` was a no-op.

It has found two real defects in its siblings. `cc`, `walkv`, `rx` and `trace`
all embedded the build directory in DWARF's `.debug_line_str`, so two builds
in differently-named directories produced different bytes -- `.debug_line_str`
grew by exactly the number of characters the second directory name was longer.
And `httpd` returned no verdict at all, because a fifo left in its test tree
made `shutil.copytree` raise and the tool die with a traceback rather than an
answer. Both are fixed; both were found by running it over all 38 rather than
the handful its own README discussed.

## Start with cc

`cc` compiles itself. `make self-host` builds it with itself, builds it again
with the result, and checks the two binaries are byte-identical.

That fixpoint proves the compiler is *stable*, not that it is *correct*. The
first time `cmp cc2 cc3` came out green the stage-2 compiler still failed 15
cases -- which is why the suite then runs in full against the stage-2 binary.

It has a preprocessor with the hide-set rules, function prototypes,
bitfields, variadic functions checked against glibc's own `va_arg`, and it
compiles `<stdio.h>` and friends out of `/usr/include`.

```sh
cd cc
make self-host      # cc -> cc2 -> cc3, cmp cc2 cc3
make diff-test      # every case against gcc and clang
```

## Unfinished, and listed rather than hidden

Three are incomplete. Each says so in its own README before anything else,
and each refuses what it has not implemented instead of answering wrongly:

- **`terminfo`** reads headers, booleans, numbers and the string table --
  4,584 string capabilities byte for byte against `infocmp` -- but not the
  ncurses extended section, and not parameterised strings against `tput`.
- **`xmlc`** has elements, attributes, character data, comments, processing
  instructions, CDATA sections and the XML declaration, but not references or
  the DOCTYPE -- so it *declines* 84% of the W3C suite rather than judging
  it. 264 judged, of which not-wf is 207/207 and invalid 55/55.
- **`zipc`** reads archives but cannot write one.

A declined case is reported separately from a passing one. That distinction is
the difference between the `897/897` above and a number that means something.

## Worth running once each

```sh
cd cc        && make diff-test                        # vs gcc and clang
cd rx        && make bench                            # 1ms where python-re takes >5s
cd walkv     && make test-asan                        # the crash matrix under ASan+UBSan
cd trace     && ./trace -cf ls                        # follow children
cd jail      && ./jail --ro /usr -- cat /etc/passwd   # denied, cleanly
cd srcdiff   && python3 srcdiff.py audit attrs        # live supply-chain audit
cd unrepro   && python3 unrepro.py check ../cc --cmd 'make -B'
```

Several compose. `cc` and `lnk` together remove the binutils dependency.
`inflate` is what `tarx` uses for compression.

## Layout

Each of the thirty-eight is an independent repository with its own history,
`README.md`, `PLAN.md` and `make test`. This repository is what sits above
them: `INDEX.md`, the working standards in `METHOD.md`, the `cq` wrapper
around `commitq`, and `.portfolio/`, which regenerates the figures above from
a real run of every suite.

GPL-3.0-or-later. Vendored conformance corpora keep their own licences beside
them.
